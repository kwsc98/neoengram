关键边界

一次 Add 如何闭环

对象先落到 StorageVolume，Index 后发布到中心；任何一步失败都不能产生半发布的权威状态。

  1. 1

    固定基线

    用户向中心提交命令；中心读取 IndexVersion，创建 Job/租约并调度到目标 Agent 的 Assignment。

  2. 2

    扫描与发布对象

    Agent watch 到 Assignment 后先写 Ledger，再稳定读取 NFS、切块并发布经过 BLAKE3 验证的对象。

  3. 3

    生成 MetadataBatch

    Agent 生成结构化 IndexDelta 与 ObjectReceipt；本地 candidate 只用于分页和恢复。

  4. 4

    中心完整校验

    Agent 幂等上传所有页面；中心验证 digest、路径、对象依赖和租户边界，再导入 staging。

  5. 5

    CAS 发布

    PostgreSQL 事务推进 IndexVersion；Agent watch 到 finalize decision 后确认并清理本地候选。

八条不可跨越的边界
命令入口 用户、CLI、UI 和自动化系统只调用 neoengramd。Agent 不接受绕过中心的业务命令或入站管理调用。
元数据权威 托管模式只有中心 PostgreSQL 权威。Agent 不直连数据库，也不上传 SQLite 数据库文件。
存储布局 一个 Volume 可放同租户多个 Artifact；一个 Artifact 每集群最多一个活动 placement。每个 Volume 只有一个 active RW Owner。
Playground 写入 多个 Agent 可以读；只有 Volume Owner 且持有排他 PlaygroundLease 和最新 fencing token 的 Agent 能写。
Snapshot 读取 Snapshot 固定 Artifact 的一个 Commit，只读且不跟随 Ref；任何修改必须进入新的 Playground。
Pod 目录挂载 PodMountBinding 只描述已有 Pod 到单个视图精确根的关系；I/O 经节点 NFS/CSI 客户端直达本集群 NFS，不负责创建 Pod、NAS、PV 或 PVC。
对象传输 集群间不直连 Agent/NFS。Gateway 只读挂载对象根；目标 Agent 拉取固定 Commit 对象，中心只签发任务和票据。
本地数据库 非权威。system DB 每 Agent 一个、Ledger 每 Tenant 一个，cache/candidate 按需创建并可重建。
