一次 Add 如何闭环

对象先落到 StorageVolume，Index 后发布到中心；任何一步失败都不能产生半发布的权威状态。

  1. 1

    固定基线

    中心读取当前 IndexVersion，创建 Job、共享读租约并选择可访问 Workspace 的 Agent。

  2. 2

    扫描与发布对象

    Agent 稳定读取 NFS 文件，按仓库策略切块并发布经过 BLAKE3 验证的对象。

  3. 3

    生成 Artifact

    Agent 生成结构化 IndexDelta 与 ObjectReceipt；本地 candidate 只用于分页和恢复。

  4. 4

    中心完整校验

    中心主动拉取所有页面，验证 digest、路径、对象依赖和租户边界，再导入 staging。

  5. 5

    CAS 发布

    PostgreSQL 事务推进 IndexVersion；中心幂等 finalize Agent 并释放租约。

四条不可跨越的边界
元数据权威 托管模式只有中心 PostgreSQL 权威。Agent 不直连数据库，也不上传 SQLite 数据库文件。
Workspace 写入 多个 Agent 可以读；同一时刻只有持有排他 WorkspaceLease 和最新 fencing token 的 Agent 能写。
对象传输 目标 Agent 直接从 NFS/Gateway 拉取，中心只签发任务和票据，不代理大对象 payload。
本地数据库 非权威。system DB 每 Agent 一个、Ledger 每 Tenant 一个，cache/candidate 按需创建并可重建。
